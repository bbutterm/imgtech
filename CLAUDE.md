# Инструкция для ИИ-ассистента

Прочитай `README.md` — там архитектура, контракты API, пороги и бэклог.
Ниже — правила работы, нарушать которые нельзя.

## Рабочий процесс

- Разработка ведётся в ветке **`dev`**. Каждый пуш автоматически собирает
  preview на Vercel — владелец проверяет его руками.
- В **`main` (прод) мержить только после явного «выкатывай»** от владельца.
- `release/v0.1-demo` — замороженная точка отката, не трогать.
- Коммиты — осмысленные, по одному изменению; после правок прогонять тесты.

## Жёсткие инварианты

1. `api/vector_compare.py` = копия `core/vector_compare.py` (+ заголовок).
   Изменил ядро — синхронизируй копию в том же коммите.
2. `python3 -m core.tests.run_tests` должен быть зелёным перед пушем.
3. Секретов в репозитории нет. Ключи Supabase в коде — публичные
   (anon/publishable), их менять/прятать не нужно. Единственный настоящий
   секрет — `QWEN_API_KEY` (режим изображений) — живёт ТОЛЬКО в переменных
   окружения Vercel; в код, коммиты и фронт не вносить.
4. Пороги ядра и API (eps, HEAVY_SHARE, склейка рамок и т.д. — таблица в
   README) калиброваны на реальных чертежах — не менять без проверки на них.
5. Согласование в UI — **по листам**, не по отдельным отличиям
   (явное требование владельца, не «улучшать» обратно).

## Особенности окружения CI-сессий

- Прямые запросы к `*.supabase.co` и `*.vercel.app` из контейнера могут
  быть закрыты прокси. Для API-тестов монкипатчить
  `api.index.verify_token`; для UI-тестов — Playwright с перехватом
  `**/auth/v1/token**` и `**/rest/v1/sessions**`.
- Управление Supabase (SQL, миграции) доступно через MCP-интеграцию.
- git-теги могут не пушиться (403) — использовать ветки-закладки.

## Команды

```bash
uvicorn api.index:app --port 8000              # API локально
cd frontend && npm run dev                     # UI (proxy /api → :8000)
cd frontend && npm run build                   # сборка перед пушем
python3 -m core.tests.run_tests                # тесты ядра
```
